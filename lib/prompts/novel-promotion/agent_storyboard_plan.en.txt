Panel mode semantics:
- `panel_mode` is the storyboard structure type. It tells the system whether this top-level panel should be generated from one representative image or from a connected group of key frames.
- `panel_mode="single"` means one image is enough: one spoken line, one stable reaction, one simple expression, one small/static action. `frames` must contain exactly 1 item with `frame_index=0`, `frame_time_sec=0`, `frame_role="hero"`, `dependency_frame_ids=[]` unless the first frame needs to continue from the previous top-level panel tail, in which case `dependency_frame_ids` may be `["FP"]`. Do not output `group_video_prompt`.
- `panel_mode="group"` means the panel is a continuous video beat needing 2-20 connected key frames, decided by duration + action density + transition/camera-movement density: visible movement, turning, walking, chasing, fighting, scene transition, multi-stage emotion/action, or clearly different beginning/end states. Frames must be chronological and later frames should depend on earlier frames through `dependency_frame_ids`.
- Do not make every panel `group` just because the user selected an 8/10/15/20 second duration preference. Use `group` only when multiple visual states are truly needed. Simple panels remain `single`.
- For group panels, `duration_sec` must be <= 20 seconds. The first frame must be the original/before-action state, not the completed result.
- Group frame count rule: 6-8s low density = 2 frames; 9-12s low/medium density = 3-4 frames; 13-16s medium/high density = 4-6 frames; 17-20s medium/high density = 5-8 frames.
- Increase frame count when there are many actions, position changes, prop interactions, multi-person interactions, scene transitions, flashbacks/dreams, or dense camera moves such as orbit, dive, tracking, whip pan, dolly, push, pull, or pass-through shots.
- Ultra-high density action/camera movement should approach 1 frame per second, capped by duration_sec, so a 20s group may use up to 20 frames. Use this for continuous fighting, melee, high-speed chase, repeated dodge/block/combo actions, explosion/falling, rapid cutting, continuous transitions, or dense whip-pan/pass-through/tracking camera combinations.
- If a non-ultra-high-density 20s beat needs more than 8 key states, split it into two top-level group panels. If it is clearly ultra-high-density action/camera movement, keep one group and output up to 20 frames.
- Top-level `props` must list visible or interacted prop asset names selected from Props info. Distinctive objects such as backpacks, bags, watches, rings, bracelets, phones, books, umbrellas, cups, cameras, keys, suitcases, weapons, magical tools, tokens, and folders must be prop assets, not character appearance. If no prop is visible or used, output `props: []`.
- `FP` means the first frame references the previous top-level panel tail frame. Use `FP` only in `frame_index=0` when continuity truly needs the previous ending state: same character position, pose, prop state, lighting, or continuous action. Do not use `FP` for a new scene, time jump, dream/flashback, or unrelated shot. The frame `reference_policy` must mention preserving continuity from the previous panel tail without copying composition.

Planning rules:
1. Keep strict chronological order.
2. Avoid missing key beats from clip_content.
3. Keep panel transitions smooth and logically continuous.
4. Use locations and characters consistent with provided libraries and mappings.
5. Prefer concrete, visible actions over abstract wording.
6. If location context contains available slots, treat them as preferred placement anchors rather than mandatory hard boundaries.
7. Prefer assigning a `slot` by copying one full placement phrase from `available_slots` verbatim when a character is stably positioned in the scene.
8. You may omit `slot` when the shot is mainly about movement, entry/exit, path traversal, transition space, temporary space, empty space, imagination, dream, memory, or abstract/non-literal space.
9. When no `slot` is used, decide placement freely from source text, action flow, and cinematic staging instead of forcing one of the provided slots.
10. Do not shorten, rewrite, summarize, or replace a provided slot phrase with a short token such as `slot_1`, `left`, or `throne_front`.
11. Every top-level panel must include `panel_mode`, `duration_sec`, and `frames`.
12. `single` panels must have exactly 1 frame. `group` panels must have 2-20 frames, based on duration, action density, and transition/camera-movement density; ultra-high-density action/camera movement may approach 1 frame per second.
13. Every panel must include `props`; use an empty array when no provided prop asset is visible or used.
13. Return strict JSON only.
14. ⚠️ JSON SAFETY: All quotation marks in text (""''「」 etc.) MUST be converted to corner brackets「」in JSON string values. NEVER use raw ASCII double quotes " inside string values.

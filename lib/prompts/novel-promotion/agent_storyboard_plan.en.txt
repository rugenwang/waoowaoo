Panel mode semantics:
- `panel_mode` is the storyboard structure type. It tells the system whether this top-level panel should be generated from one representative image or from a connected group of key frames.
- `panel_mode="single"` means one image is enough: one spoken line, one stable reaction, one simple expression, one small/static action. `frames` must contain exactly 1 item with `frame_index=0`, `frame_time_sec=0`, `frame_role="hero"`, `dependency_frame_ids=[]`. Do not output `group_video_prompt`.
- `panel_mode="group"` means the panel is a continuous video beat needing 2-20 connected key frames, decided by duration + action density + transition/camera-movement density: visible movement, turning, walking, chasing, fighting, scene transition, multi-stage emotion/action, or clearly different beginning/end states. Frames must be chronological and later frames should depend on earlier frames through `dependency_frame_ids`.
- Duration and timeline are mandatory before output: count all Chinese dialogue/voiceover/inner-monologue characters in `source_text`; pure speaking time is 2-3 Chinese characters per second. `duration_sec` must not be shorter than pure speaking time, and must also include action time, pauses, camera/transition time, and environment/establishing buffer.
- The sum of all timeline ranges in `video_prompt` / `group_video_prompt` must equal `duration_sec`; the timeline must start at 00:00 and the final range must end exactly at `duration_sec`.
- `frames.frame_time_sec` must use the same timeline: frame_index 0 must be 0, later frame_index values must increase in playback order, and the final key state should be at or near the tail of `duration_sec`.
- A single top-level panel/group must not exceed 20 seconds. If dialogue + action + pauses + camera/environment time exceeds 20 seconds, split into another top-level panel/group instead of compressing the dialogue.
- Do not make every panel `group` just because the user selected an 8/10/15/20 second duration preference. Use `group` only when multiple visual states are truly needed. Simple panels remain `single`.
- For group panels, `duration_sec` must be <= 20 seconds. The first frame must be the original/before-action state, not the completed result.
- Group frame count rule: 6-8s low density = 2 frames; 9-12s low/medium density = 3-4 frames; 13-16s medium/high density = 4-6 frames; 17-20s medium/high density = 5-8 frames.
- Increase frame count when there are many actions, position changes, prop interactions, multi-person interactions, scene transitions, flashbacks/dreams, or dense camera moves such as orbit, dive, tracking, whip pan, dolly, push, pull, or pass-through shots.
- Ultra-high density action/camera movement should approach 1 frame per second, capped by duration_sec, so a 20s group may use up to 20 frames. Use this for continuous fighting, melee, high-speed chase, repeated dodge/block/combo actions, explosion/falling, rapid cutting, continuous transitions, or dense whip-pan/pass-through/tracking camera combinations.
- If a non-ultra-high-density 20s beat needs more than 8 key states, split it into two top-level group panels. If it is clearly ultra-high-density action/camera movement, keep one group and output up to 20 frames.
- Top-level `props` must list visible or interacted prop asset names selected from Props info. Distinctive objects such as backpacks, bags, watches, rings, bracelets, phones, books, umbrellas, cups, cameras, keys, suitcases, weapons, magical tools, tokens, and folders must be prop assets, not character appearance. If no prop is visible or used, output `props: []`.
- Do NOT output `FP` during initial storyboard planning. Previous-tail linking is a manual storyboard-page option and will be added by the system only after the user enables it. If a panel seems suitable for previous-tail continuity, mention it only in `description` or `reference_policy.note`; do not put `FP` in `dependency_frame_ids` or `ordered_references`.
- Every frame, including `panel_mode="single"`, must include `reference_policy.ordered_references`. This tells downstream image generation what each input reference image means.
- Ordered reference sequence must be: dependency frame references first, then location reference image(s), then character reference image(s) in `characters` order, then prop reference image(s) in `props` order.
- `frame.image_prompt` must start by explaining the input reference order, for example: `Input references F1-F2 are Office scene references, F3 is character image: Lin Wan · default, F4 is prop folder; current still image...`. Here F1/F2/Fn means input reference image order, not storyboard keyframe numbers.
- In every `frame.image_prompt`, each visible person must be written as age/gender/temperament + character name, not a generic label only. Good examples: `young woman Lin Wan stands on screen-left`, `middle-aged man Mr. Wang sits behind the desk`, `young man Lu Ze looks toward the doorway`. If age/gender is uncertain, still include the character name with the action.
- A single panel should still be treated as a one-frame group for image planning: `frame_index=0`, `frame_role="hero"`, one representative image prompt, and a complete reference policy for location/characters/props.
- Location can use multiple reference images when the shot needs multiple spatial anchors such as room layout, hallway direction, furniture, doors/windows, or indoor/outdoor relationship. Explain which location reference controls which spatial part in `reference_policy` and `image_prompt`.

Planning rules:
1. Keep strict chronological order.
2. Avoid missing key beats from clip_content.
3. Keep panel transitions smooth and logically continuous.
4. Use locations and characters consistent with provided libraries and mappings.
5. Prefer concrete, visible actions over abstract wording.
6. If location context contains available slots, treat them as preferred placement anchors rather than mandatory hard boundaries.
7. Prefer assigning a `slot` by copying one full placement phrase from `available_slots` verbatim when a character is stably positioned in the scene.
8. You may omit `slot` when the shot is mainly about movement, entry/exit, path traversal, transition space, temporary space, empty space, imagination, dream, memory, or abstract/non-literal space.
9. When no `slot` is used, decide placement freely from source text, action flow, and cinematic staging instead of forcing one of the provided slots.
10. Do not shorten, rewrite, summarize, or replace a provided slot phrase with a short token such as `slot_1`, `left`, or `throne_front`.
11. Every top-level panel must include `panel_mode`, `duration_sec`, and `frames`.
12. `single` panels must have exactly 1 frame. `group` panels must have 2-20 frames, based on duration, action density, and transition/camera-movement density; ultra-high-density action/camera movement may approach 1 frame per second.
12.1 Duration must follow the 2-3 Chinese characters per second dialogue rule, plus action/pause/camera/environment time. Keep `duration_sec`, prompt timeline end time, and `frames.frame_time_sec` aligned.
13. Every panel must include `props`; use an empty array when no provided prop asset is visible or used.
13. Return strict JSON only.
14. Every frame must include `reference_policy.ordered_references` in the order `dependency frames -> location image(s) -> character image(s) -> prop image(s)`, and every `frame.image_prompt` must explain what input reference F1/F2/Fn means. Do not output FP during planning.
15. ⚠️ JSON SAFETY: All quotation marks in text (""''「」 etc.) MUST be converted to corner brackets「」in JSON string values. NEVER use raw ASCII double quotes " inside string values.
